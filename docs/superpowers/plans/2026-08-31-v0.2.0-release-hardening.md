# MetaAgent v0.2.0 Release Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a reproducible, protected, and fully documented MetaAgent v0.2.0 release whose source, CI, tags, release metadata, and GitHub repository settings agree.

**Architecture:** Keep the Quart and MCP application unchanged while hardening its packaging, CI, container launch path, contributor workflow, and release process. Apply source changes on a release branch, verify locally, merge only after GitHub Actions succeeds, then configure repository protections and publish an annotated tag and GitHub Release.

**Tech Stack:** Python 3.11/3.12, Quart, FastMCP, pytest, setuptools, Docker, GitHub Actions, Dependabot, CodeQL, GitHub CLI.

**Spec:** The approved repository audit in the preceding project review.

## Global Constraints

- Keep `.env`, API keys, runtime databases, uploads, and user history local and untracked.
- Preserve the public contribution boundary and do not restore company-specific services or data.
- Keep the app's Quart, SQLite, SSE, and MCP runtime behavior unchanged.
- Publish the next release as `v0.2.0` from a clean, verified `main` commit.
- Require current CI checks before future changes can merge into `main`.
